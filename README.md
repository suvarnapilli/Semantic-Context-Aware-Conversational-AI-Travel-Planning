# ✈️ AI Travel Planner

A full-stack AI-powered travel planning web app built with **React + Vite** (frontend) and a **Python/Node.js backend**. Users sign in with Clerk, describe their trip, and get a personalized itinerary generated by **Google Gemini AI** — with real-time chat-based modifications, flight availability search, hotel search, Google Maps navigation, travel history, and PDF download.

---

## 🌟 Features

- **🔐 Authentication** — Secure sign-in/sign-up via [Clerk](https://clerk.dev), with a custom teal theme
- **🤖 AI-Generated Itineraries** — Full day-by-day travel plans covering overview, transport, budget, stays, and tips
- **💬 Conversational Itinerary Editor** — Chat with Gemini to modify any part of your plan; confirm or reject changes with YES/NO
- **✈️ Flight Search** — Search live flight availability by city name or airport code via Amadeus API
- **🏙️ Airport Lookup** — Search airports from a local JSON database by city name or IATA code
- **🏨 Hotel Search** — Find hotels by city name via backend API
- **🗺️ Google Maps Navigation** — One-click navigation from your current location
- **📜 Travel History** — View all past itineraries saved to your account
- **📄 PDF Download** — Download any saved itinerary as a PDF
- **🎤 Voice Input** — Speak any field using the Web Speech API
- **📱 Responsive UI** — Clean, card-based interface with hover animations and mobile breakpoints

## 🗄️ Database Schema

Three tables managed in **SQLite** with foreign key constraints:

| Table | Description |
|---|---|
| `users` | Clerk user ID, name, email, created_at |
| `travel_requests` | Trip details per user (city, destination, dates, budget, style, etc.) |
| `travel_plans` | Final itinerary text + optional PDF path, linked to a request |

```sql
-- Users synced from Clerk on first form submit
CREATE TABLE users (id TEXT PRIMARY KEY, name TEXT, email TEXT UNIQUE, ...);

-- One row per trip planning request
CREATE TABLE travel_requests (id, user_id, current_city, destination, start_date, end_date, budget, ...);

-- Stores AI-generated itinerary; 1:1 with travel_requests
CREATE TABLE travel_plans (id, user_id, request_id UNIQUE, final_itinerary TEXT, pdf_path TEXT, ...);
```

## ⚙️ How It Works

### 1. Itinerary Generation (`ai_travel.py`)
- Receives trip details from the frontend via the backend API
- Determines seasonal weather context from the travel month
- Builds a structured prompt and calls **Gemini 2.5 Flash**
- Returns a plain-text itinerary with strict formatting: Trip Overview → Transport → Budget → Stays → Day-by-Day → Tips

### 2. Chat Modifications (`chat_loop.py`)
- Keeps the current itinerary as context on every call
- Classifies the user message: general question vs. modification request
- On modification: proposes full updated itinerary + asks for YES/NO confirmation
- On YES: applies and saves the update; on NO: discards cleanly

### 3. Frontend Pages (`App.jsx`)
| Page | Description |
|---|---|
| Home | Hero landing page with background image and CTA |
| Form | 8-field travel form with voice input on every field |
| Itinerary + Chat | Displays generated plan; inline chat to modify it |
| Booking API | Airport lookup, flight availability search, hotel search |
| Maps | Opens Google Maps navigation from current location |
| History | Lists all past trips; click to view full itinerary + download PDF |

### 4. Flight & Airport Search (`BookingAPI.jsx`)
- Airport lookup runs locally against `airports.json` (no API call)
- Flight search sends origin/destination codes + date to `/api/flight-availability` (Amadeus API)
- Results are filtered client-side to match the exact destination code
- Hotel search hits `/api/hotels-by-city-name` on the backend

## 🚀 Getting Started

### Prerequisites

- Node.js 18+ and npm
- Python 3.9+
- A [Google Gemini API key](https://aistudio.google.com/app/apikey)
- A [Clerk account](https://clerk.dev) (free tier works)
- Amadeus API credentials (for live flight/hotel search)

### 1. Clone & Install

```bash
git clone https://github.com/your-username/ai-travel-planner.git
cd ai-travel-planner

# Frontend
cd frontend
npm install

# Backend Python deps
pip install google-generativeai python-dotenv requests
```

### 2. Environment Variables

Create a `.env` file in the backend root:

```env
GEMINI_API_KEY=your_gemini_api_key_here
AMADEUS_CLIENT_ID=your_amadeus_client_id
AMADEUS_CLIENT_SECRET=your_amadeus_client_secret
```

Update the Clerk publishable key in `main.jsx`:

```js
const PUBLISHABLE_KEY = "pk_test_your_clerk_key_here";
```

### 3. Initialize the Database

```bash
sqlite3 database.db < schema.sql
```

### 4. Run the App

```bash
# Start backend (port 5000)
node server.js     # or: python app.py

# Start frontend (port 5173)
cd frontend
npm run dev
```

Open `http://localhost:5173` in your browser.

## 🧠 AI Prompt Design

The itinerary prompt enforces strict formatting rules:

- Groups days when the trip exceeds 6 days
- Max 3 transport options, exactly 4 budget lines, 3 accommodation suggestions
- Time slots are specific (e.g. `9:00`, `13:00`) — no vague "Morning/Afternoon" labels
- Meal suggestions embedded inline within the daily schedule
- Max 5 essential tips with green tick emoji formatting
- No markdown symbols (`*`, `` ` ``, `#`) in the output

### Chat Modification Protocol

```
User: "Change day 2 to include a sunset cruise"
  → AI detects modification intent
  → Returns full updated itinerary
  → Appends: "Reply YES to confirm changes or NO to cancel."
  → Frontend holds updated_itinerary as pending_update
  → User: "yes" → saved; "no" → discarded
```
